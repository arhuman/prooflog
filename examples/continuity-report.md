## 2. What this report proves — and what it does not

This report is produced from **metadata only**: sequence numbers, hash
chains, Merkle roots, segment signatures, and heartbeats. Event payloads
are encrypted on the client before upload; neither the storage operator
nor this Verifier can read them.

**Proven, cryptographically:**

- every event accepted by an agent during the period is present, in
  order, unmodified (hash chain + segment signatures + Merkle roots);
- no accepted event was deleted or inserted retroactively (monotonic
  sequence + chained hashes);
- collection continued through network outages without loss (buffered
  sequence ranges match replayed segments);
- the periods during which each source was demonstrably alive and able to
  log (signed heartbeats).

**Not provable, by design — stated honestly:**

- events an application never emitted cannot be reconstructed;
- what happened during an unobserved window (no running agent = no
  evidence, only the boundary of the window is proven);
- wall-clock accuracy beyond the monitored clock drift (§5.4);
- payload contents (encrypted; verification is content-blind);
- **no gap detected ≠ no event was omitted before it reached the agent** —
  guarantees begin at agent acceptance; upstream suppression is invisible
  by construction;

## 7. Privacy manifest

Each envelope field's disclosure level:

| Field | Disclosure |

## 9. Trust assumptions & limitations

This report is trustworthy under the following assumptions, stated
explicitly:

1. **Verifier independence.** This report was generated by a verification
   service operated by a third party, independent from the operator of the
   Store. Rewriting stored history without detection would
   require compromising the agents, the store, **and** this service.
2. **Agent key integrity.** Events are signed with per-agent keys held on
   the source hosts. An attacker holding an agent's key could forge
   *new* events from that source (never rewrite anchored past ones).
   No key revocation events were recorded during the period.
3. **Self-hosted caveat.** In fully self-hosted deployments where one
   operator runs agents, store, and verifier, this separation does not
   hold; such reports must state it. (Not the case here.)
4. **Coverage boundary.** Prooflog proves the integrity and continuity of
   *accepted* events. It does not observe the host beyond what agents
   emit, and it is not a legal guarantee of compliance.
